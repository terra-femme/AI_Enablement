# Tier 1.5 — Saving, Organizing & Finding Your AI Work
### For non-technical teams (no GitHub, no git, no jargon)

**Audience:** every employee + team leads
**Why this module exists:** non-technical staff have no concept of version control, yet they ask on day one: "Where did my work go? How do I keep it? How do I find it again?" Answer it before they invent messy habits (saving to desktop, losing chats, re-doing work).

**The one-line hook:**
> *"You don't need GitHub. Your cloud drive's 'Version History' is your save button — and your AI chats live in Projects."*

**Teaching rules:** one idea per asset, demo-before-theory, rule of 3, analogy-first. Each numbered item below = one standalone asset.

---

## 1.5.0 — The mental model (the hook)
Developers obsess over "saving progress" with tools like git. Non-technical teams **already own the same capability** — they just don't know it's there.

> Analogy: git is a professional photographer's contact sheet of every shot. You don't need that. You need the **"Version History"** button your file storage already has — same idea, one click.

**Three places your AI work lives, and that's it:**
1. **Inside Claude** — work in progress (chats, projects).
2. **Your cloud drive** — finished documents.
3. **A shared reference space** — reusable prompts/templates.

**So what / now what:** stop saving to the desktop. Stop losing chats. Everything has a home.

---

## 1.5.1 — Saving work *inside* Claude (work in progress)
- **Projects** — group related chats and attach reference docs so Claude keeps consistent context. This is the team's "saved workspace" for an ongoing effort (e.g., "Q3 Client Onboarding").
- **Conversation history** — past chats are retained and searchable; you can reopen and continue them.
- **Artifacts / outputs** — documents Claude builds can be copied or downloaded out into your drive.

> ⚠️ **Verify before teaching:** confirm the firm's actual Claude Enterprise settings (retention period, Projects availability/limits, export options) in their admin console. Do not present these specifics from memory in a paid session.

**Three habits to teach:**
1. Start a **Project** for any multi-day effort — don't start fresh chats each time.
2. Give chats **clear titles** so history is searchable later.
3. When work is "done," **move the output out** into the cloud drive (next section).

---

## 1.5.2 — Saving finished work in tools they already own (the real "save button")
The non-technical equivalent of version control is **cloud storage with version history** — they already pay for it:
- **OneDrive / SharePoint** (Microsoft shops), **Google Drive** (Google shops), **Dropbox**.
- Every one of these keeps **automatic version history**: right-click a file → *Version history* → restore any earlier version. **That is "git" for normal people.**

**Three habits:**
1. Save AI outputs into the **shared team drive**, not a personal desktop.
2. Trust **Version History** instead of saving `final_v2_FINAL_really.docx` copies.
3. One **folder + naming convention** per team, taught once, followed always.

> Demo idea: edit a doc, delete a paragraph, then restore it from Version History live. The "oh!" moment sells the whole module.

---

## 1.5.3 — Reusable assets: the team prompt library
The thing teams lose most: **good prompts**. Capture them once.
- A shared **doc / SharePoint page / Notion** of "prompts that work here."
- Or **Claude Project custom instructions** for prompts a whole team reuses.

**Three to start:** the team's 3 most-repeated tasks → write the prompt once → save it → everyone reuses it.

---

## 1.5.4 — Bridge to governance (Tier 3)
"Where work is saved" *is* a governance question — connect it, don't silo it:
1. **Retention** — how long are AI chats/outputs kept? (admin-controlled)
2. **Access** — who can open the shared drive / Project? (least privilege)
3. **Classification** — confidential/regulated work follows the data-handling rules from Tier 3, *wherever* it's saved.
